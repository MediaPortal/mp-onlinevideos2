# Migrate OnlineVideos server to .NET 10 and harden client-facing APIs

The existing server uses .NET 6 and trusts several write operations too broadly. This change targets .NET 10, updates EF Core SQLite/Swagger dependencies and replaces ImageSharp with SkiaSharp while retaining the existing image format/ratio behavior and original bytes.

The server now migrates legacy passwords to salted hashes, disables password email and public registration, requires HTTPS for sensitive operations, and enforces account/IP/concurrency/resource limits. Anonymous client reports remain unverified; only owners/admins may moderate provider status. Approved publishers can stage managed DLLs privately, but publication requires an explicit local operator approval with SHA-256 verification. Uncatalogued or staged files cannot be downloaded through the public API.

The web frontend retains antiforgery protection, uses bounded queries and secure cookies, and invalidates sessions after password/role changes. XML, image, filename and DTO constraints reject malformed or oversized requests. Read response shapes and legacy MD5 change checksums are retained; intentional write-policy changes and required publisher/client workflow adaptations are documented in SECURITY-HARDENING.md.

Validation: 33 security regression checks and 15 image/SQLite checks passed on Windows; 14 smoke assertions passed against an isolated Debian 12 deployment; Release build and self-contained Linux publish succeeded. The production binary and service were preserved. The proposed GitHub workflow has not run on GitHub. Historical pre-hardening HTTP comparisons are retained as historical evidence, not as current write-policy tests.

Deployment requires a protected database backup, trusted TLS proxy, private data directory and service limits. Password conversion is one-way for the old application, so rollback uses the paired old database backup. Debian 13, full MP2 video playback and end-to-end package signature verification remain outside the completed validation. No client changes or production cutover are included.

The account-management extension adds User/Publisher/Administrator roles, invitation-only provisioning, email confirmation, password changes, account suspension/deletion with retained contributions, and opt-in queued mail. Site definitions now remain pending until administrator review; DLL approval still requires the local operator. The frontend follows LogoManager styling with independent OnlineVideos branding and licensed generic replacement icons. Validation now includes 62 security/account/SMTP checks and 15 image/SQLite checks; the HTTPS test deployment was checked without a production cutover.
