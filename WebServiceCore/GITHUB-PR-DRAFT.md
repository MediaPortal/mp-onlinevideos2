# Migrate OnlineVideos server to .NET 10 and harden client-facing APIs

WebServiceCore currently targets .NET 6. This PR migrates the server to .NET 10, updates EF Core SQLite and Swagger, and replaces ImageSharp with SkiaSharp while retaining existing image bytes and output behavior. Client projects are unchanged.

Authentication now uses salted password hashes, HTTPS for sensitive operations, current transactional permission checks, durable session revocation, and account/IP/concurrency/resource limits. Strict XML, image, filename and request validation protects client-facing write endpoints. Anonymous reports remain unverified. DLLs are staged privately, validated as managed assemblies and bound to SHA-256 hashes; active administrators can inspect, approve or reject them in the browser. The local operator approval command remains available.

Browser account management supports User, Publisher and Administrator roles; invitation-only provisioning with expiring one-use links; verified notification email addresses separate from login names; password changes requiring the current password; and account suspension/deletion while preserving contributions. Self-removal and removal of the last active administrator are prevented. Opt-in queued email covers pending submissions, hourly report summaries and decisions, with recipient revalidation, shared-mailbox deduplication and bounded SMTP retries.

Site submissions remain private until reviewed (SubmitSite returns HTTP 202 and a review identifier). Reviews are grouped into combined XML/DLL, XML-only and DLL-only submissions. Matching package names and submitters allow a single Approve or Reject action for both XML and the exact selected DLL version, with fresh authorization/hash checks, one database transaction and file rollback on publication failure. DLL inspection downloads remain private, checksum-bound attachments. Related DLL cards are not duplicated below the XML. Existing clients can submit XML that depends on a DLL still awaiting approval.

The frontend adds independent OnlineVideos branding, working catalogue sorting, spacing for long site names/report counts and consistent download buttons. Removed replacement icons are not included. English migration, security, account/mail and rollback documentation is included under WebServiceCore.

Validation: 112 security/account/SMTP regression checks and 15 image/SQLite checks have passed locally on Windows. HTTPS deployment checks cover login, administrator pages, exact private DLL downloads and the grouped review controls. Earlier Debian 12 smoke and installed MP2 HTTPS API/catalogue checks are documented; MP2 playback remains unverified because of its provider/core version mismatch. The latest GitHub Actions result is recorded below once the updated workflow completes. Test SMTP uses an isolated listener, not real recipients.

Deployment requires a protected database backup, a trusted TLS proxy, a private staging directory and appropriate service limits. Schema migration/password conversion requires the paired previous application and database for rollback. This PR does not switch the production service. Debian 13 and end-to-end package signature verification remain outside completed validation.
